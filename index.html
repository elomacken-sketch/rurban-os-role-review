Rurban OS 四角色界面外部评审

这是无需 JavaScript 的静态评审入口。网页抓取工具可以直接读取全部文字，并通过四张页面截图评估真实桌面端视觉。需要实际点击时，再进入只读交互版。

模型完整评审文档 老板 运营 招商 商户 打开只读交互版

评审边界：只评价信息架构、视觉专业度、结果展示方式和操作理解成本；不评价模拟数据真实性，不执行写入、生成、发布或下载。

统一产品逻辑

同一套系统、同一份数据、四种角色视图。运营产生的内容与执行结果会进入老板决策和招商材料；商户提交会影响运营排期与经营反馈；招商反馈会回传运营和老板。不同角色看到不同入口，但不是四套彼此割裂的产品。

输入原则

  • 项目资料一次录入，月份和目标按月补充。
  • 用户只填写少量变化、预算、优先级和真实反馈。
  • 复杂分析、文档、日历、任务和材料由系统组织。

输出原则

  • 经营判断使用指标、图表和决策表。
  • 内容方案使用文档、平台预览和日历。
  • 招商使用候选画像、材料清单和推进状态。
  • 商户使用最少字段的分步任务。

老板视图

老板首屏只看一句话现状、今天需要决定的三件事，以及距离第一条经营反馈还差几步；其他内容进入后续栏目。

结果与决策

左侧栏目

  1. 项目经营总览
  2. 月度战役与审批
  3. 执行与协同进展
  4. 经营价值与趋势
  5. 下月决策与月报

主要展示形式

  • 一句话经营现状
  • 三项待决定事项
  • 下一步进度
  • 月度方案演示文稿
  • 协同进展与下月决策

运营视图

运营围绕今天做什么、缺什么、如何快速形成内容和如何组织执行展开，不承担老板决策页的信息密度。

生成与执行

左侧栏目

  1. 今日工作台
  2. 内容日历与活动
  3. 内容生产

主要展示形式

  • 优先任务列表
  • 内容日历与审核节点
  • 小红书、公众号、短视频切换
  • 内容成品预览
  • 负责人、截止时间和素材缺口

招商视图

招商使用运营产出的内容和经营证据形成品牌画像、铺位匹配理由及沟通材料，并把真实疑虑和跟进状态回传系统。

线索与材料

左侧栏目

  1. 招商推进总览
  2. 品牌画像与候选库
  3. 铺位与招商材料
  4. 商户协同反馈

主要展示形式

  • 招商推进状态摘要
  • 候选品牌画像卡片
  • 推荐理由、适配位置和验证项
  • 招商弹药清单
  • 商户参与任务与反馈表

商户视图

商户不进入完整项目后台，只看到本月主题、截止时间和自己需要完成的少量任务。

简单任务

任务步骤

  1. 提交产品与价格
  2. 上传图片与真实故事
  3. 确认内容、活动和传播参与方式

主要展示形式

  • 三步进度条
  • 每次只显示一项任务
  • 简单输入框和图片入口
  • 主题价值和提交标准
  • 信息可修改、结果需确认

请回答这些评审问题

  1. 每种角色能否在 5 秒内理解当前页面最重要的结果？
  2. 四种角色的左侧入口是否真正不同并符合岗位习惯？
  3. 图表、表格、文档、日历、卡片和任务页是否用在合适的结果类型上？
  4. 老板页是否足够结果优先，而不是运营过程堆叠？
  5. 运营页是否能支持内容生成、排期、审核和执行？
  6. 招商页是否体现内容运营如何转化为招商弹药？
  7. 商户页是否足够简单，填写少但能形成细致结果？
  8. 整体视觉是否具有专业项目经营系统的可信度？

只读评审包：无 API、无数据库、无账号、无真实写入。交互入口中的操作仅在当前浏览器模拟，刷新后还原。
